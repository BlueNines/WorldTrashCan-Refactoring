## 执行规则

- 后续测试默认只部署 `dist/BLWorldTrashCan-universal.jar`，除非明确要验证轻量特供 jar。
- 玩家可见功能必须保留真实客户端截图或等价客户端侧证据，服务端日志只作为辅助排障。
- 不删除测试服 `logs`、`world*`、`cache`、`assets`。
- 每个独立修复完成后都要更新 README、矩阵或本清单，并提交、推送到当前插件仓库。
- 需要重新打包时，先运行 `build\tools\apache-maven-3.9.9\bin\mvn.cmd -q clean package`，再运行 `py -3 tools\rgb-visual-matrix\sync_dist_jars.py`，确保后续测试默认使用的 `dist` 不是旧包。
- 同步 `dist` 后必须运行 `py -3 tools\rgb-visual-matrix\check_dist_package_integrity.py`，确认交付 jar 的 `plugin.yml`、主类、默认资源、bStats 类与入口启动、插件配置无 bStats 关闭项、PrismaticAPI 重定位、新旧核心权限声明和 universal 四平台实现没有退化。
- 同步并记录新 SHA 后必须运行 `py -3 tools\rgb-visual-matrix\check_current_dist_hash_docs.py`，确认 README、长期清单和执行记录没有继续引用旧的当前交付包。
- 更新任意 `plugin.yml` 后必须运行 `py -3 tools\rgb-visual-matrix\check_plugin_yml_parity.py`，确认源码和 dist 包内插件元数据、softdepend、命令别名、权限节点和默认值没有分叉。
- 更新完整功能矩阵后必须运行 `py -3 tools\rgb-visual-matrix\check_function_matrix_doc.py`，确认 F-001 起连续编号、历史 `SKIP` 收敛说明和当前未收敛声明没有回退。
- 更新命令帮助、语言文件或调试命令后必须运行 `py -3 tools\rgb-visual-matrix\check_command_help_separation.py`，防止具体 `debug*` 命令重新混入普通帮助面板。
- 更新 `plugin.yml`、命令入口或旧别名兼容时必须运行 `py -3 tools\rgb-visual-matrix\check_command_entrypoints.py`，确认新旧命令声明、dist 包内声明和运行时注册没有退化。
- 更新任意平台命令类时必须运行 `py -3 tools\rgb-visual-matrix\check_command_parity.py`，确认五个平台普通子命令、完整子命令、处理分支和关键补全保持一致。
- 更新任意 `messages/message_*.yml` 后必须运行 `py -3 tools\rgb-visual-matrix\check_message_key_parity.py`，确认四个平台、多语言和 dist 包内语言资源的键路径与节点类型保持一致。
- 更新任意默认语言 `messages/message_*.yml`、RGB 渲染器或低版本降级逻辑后必须运行 `py -3 tools\rgb-visual-matrix\check_default_language_rgb_messages.py`，确认源码和 dist 内默认多语言消息保持 RGB、没有残留传统颜色码，并且 `&a` 兼容和 RGB 降级逻辑没有退化。
- 更新任意默认配置资源后必须运行 `py -3 tools\rgb-visual-matrix\check_default_resource_key_parity.py`，确认四个平台和 dist 包内默认配置资源的键路径与节点类型保持一致。
- 更新 PAPI 变量、PlaceholderAPI 注册入口或通用总包 PAPI 逻辑后必须运行 `py -3 tools\rgb-visual-matrix\check_papi_placeholder_parity.py`，确认 `%Wtc_ClearTime%` 在五个平台和 dist 包内没有分叉。
- 涉及世界垃圾桶或实体限制扫描时必须运行 `py -3 tools\rgb-visual-matrix\check_chunk_load_guards.py`，防止重新引入强加载 chunk 或未保护的 `getChunkAt`。
- 更新真实客户端、外部测试服或证据生成脚本时必须运行 `py -3 tools\rgb-visual-matrix\check_test_script_destructive_guards.py`，防止脚本删除测试服 `logs`、`world*`、`cache`、`assets` 或递归删除真实服务端目录。
- 更新 `run_delivery_audits.py`、README、长期清单或执行记录中的预检数量时必须运行 `py -3 tools\rgb-visual-matrix\check_delivery_audit_docs.py`，确认统一预检文档口径没有保留旧数字。

## 已确认但需要避免回退的行为

- `/wtc clear`、`/blwtc clear` 默认等价 `true`，会忽略 guards；传入 `false` 时才遵守 guards。
- `notify.console` 必须独立于 `notify.chat.enabled`；实体名称按自定义名、`getName()`、`getType()` 降级，颜色不同的同名实体合并，`items` 使用成功处理的物品实际数量。
- `guards.min-total-entities` 默认值是 `150`。
- `global-trash.clear-every-cleanups` 触发时必须先清空旧公共垃圾桶，再收集本轮物品。
- 新版本物品入桶必须保留原物品，不允许因 legacy material 映射或日志异常丢失。
- 密集实体 `remove-count` 表示触发后本轮最多清理多少只，不是只清理超出上限的差值。
- 密集实体候选队列是一次性消费队列，不是长期状态表。
- 公共黑名单 GUI 使用 token 点击模型：点击玩家背包物品复制 Material token，不消耗物品；点击上方 token 删除；关闭 GUI 后保存并刷新运行期配置。
- 外部语言文件缺节点时优先回退当前语言的 jar 内置节点，再回退默认中文；旧外部语言主帮助包含调试命令时也必须使用当前语言的 jar 内置主帮助。
- Vault 扣费只用于个人垃圾桶取出；必须先确认物品能完整进入玩家主背包存储槽，再调用 Economy 扣费，余额不足或背包满都不能产生扣款。
- Evidence 目录中的备份 jar 只作为本地恢复缓存，不提交到 Git；最终证据只记录被测 jar 文件名、版本和 SHA256。
- 新增或调整证据目录后，必须运行 evidence 索引审计脚本，防止最终证据误指向 FAIL 目录、失败对照没有说明原因、备份 jar 被重新纳入 Git。
- 新增或调整完整功能矩阵后，功能 ID 必须从 F-001 起连续，历史 `SKIP` 项必须写明后续收敛或明确不适用，当前未收敛通用专项不能被悄悄写回非“无”状态。
- 新增或调整普通帮助、调试帮助、语言文件、tab 补全或 debug 命令时，普通帮助面板和空前缀补全只能出现 `/blwtc debughelp` 入口，不能重新展示具体 `debug*` 命令。
