# 新旧版本功能与性能数据对比

本文只介绍服主能够直接使用或观察到的变化。兼容新版本、代码重写、配置拆分、RGB 修复等内容不计为新增玩法。

## 真正新增的功能

| 功能 | 旧版本 | 重构版 |
| --- | --- | --- |
| 公共垃圾桶布局 | 固定 6 行、每页 45 个内容槽 | 支持 1-6 行字符布局，每页最多 54 个内容槽，可配置内容区、翻页按钮和背景位置 |
| 公共垃圾桶按钮 | 固定上一页、下一页和背景板 | 每种按钮可配置材质候选、CustomModelData、名称、Lore 和不可用时的替代物品 |
| 布局缩容保护 | 没有布局缩容 | 容量缩小时旧物品进入临时溢出页，可查看和取出，不会被静默删除 |
| 个人垃圾桶提示 | 物品进入个人垃圾桶时没有完整提示 | 支持单个回收提示和扫地批量提示，默认完整显示前 3 类物品 |
| 扫地启动条件 | 到时间就执行 | 默认无人在线或目标实体少于 150 时跳过，可分别配置 |
| 手动扫地 | 直接执行 | `/wtc clear [true/false]` 可选择忽略或遵守扫地启动条件 |
| 公共垃圾桶放入控制 | 主要依赖权限 | 增加总开关，可统一禁止玩家手动放入 |
| 运行状态查询 | 主要依赖倒计时变量 | `/wtc stats` 可查看 8 类数据：世界、回收、删除、库存、页数、个人垃圾桶和剩余时间等 |
| 控制台清理明细 | 主要显示总数 | 默认显示清理数量最多的 10 类实体，并显示实体名称、类型、数量、其他实体总数和物品实际个数 |

按配置结构统计，重构版真正增加了约 **25 个业务配置字段或消息模板**。其余新增配置主要用于性能预算、Folia 调度、旧配置迁移和平台兼容，不计为新功能。

## 性能数据估算

以下数据根据新旧代码的执行次数和默认配置计算，不是 Spark 实测结果。实际提升与加载区块、实体数量和玩家活动有关。

| 测试场景 | 旧版本估算 | 重构版估算 | 预计减少 |
| --- | ---: | ---: | ---: |
| 1000 个加载区块的密集实体周期检查 | 约等价检查 100 个区块/秒，另有移动事件检查 | 默认约 4 个区块/秒 | 约 96% |
| 4096 个加载区块的密集实体周期检查 | 约等价检查 409.6 个区块/秒，另有移动事件检查 | 默认约 14 个区块/秒 | 约 96.6% |
| 世界有 5000 个实体，每秒生成 20 只受限实体 | 约 100000 次实体遍历/秒 | 约 20 次缓存查询，加后台分批扫描 | 生成事件路径约 99.98% |
| 无玩家在线时触发自动扫地 | 仍执行整轮扫地 | 直接跳过 | 接近 100% |
| 世界垃圾桶位于未加载区块 | 可能同步加载区块 | 默认不加载 | 插件主动强加载减少 100% |
| Folia 单轮处理 4096 个区块 | 任务可能集中派发 | 默认每批 64 个、间隔 1 Tick | 瞬时派发峰值理论减少 98.4% |

综合估算：

- 开启密集实体限制的大型服务器，相关主线程负担预计降低 **80%-99%**。
- 只使用普通定时扫地的服务器，通常降低 **0%-30%**。
- 如果旧版本主要卡在世界垃圾桶同步加载区块，单次清理卡顿峰值可能降低 **90% 以上**。
- 新版实体索引预计额外占用约 **5-10MB** 内存，以换取更低的主线程扫描压力；索引和候选队列都有数量上限。

## 需要说明的限制

- 玩家在线且达到扫地条件后，普通 Bukkit/Spigot 扫地仍要遍历当前世界实体，因此这一部分没有 80%-99% 的提升。
- `min-total-entities` 需要先统计目标数量，实体不足时仍会发生一次计数扫描。
- 世界实体数量限制改为缓存判断，性能更高，但大量实体瞬间生成时可能短暂超过上限，之后再收敛。
- 当前损坏回收只处理仙人掌、岩浆和火焰类伤害，尚未包含虚空回收。

## 一句话结论

重构版真正新增的是公共垃圾桶布局、个人回收提示、扫地门禁、运行统计和更详细的清理日志。最大的性能提升集中在密集实体限制和避免强制加载区块，普通定时扫地本身暂时没有数量级提升。
