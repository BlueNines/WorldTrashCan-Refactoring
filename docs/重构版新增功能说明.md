# WorldListTrashCan 重构版新增功能说明

本文面向服主和做服技术，说明重构版相对旧 `WorldListTrashCan` 多出的功能和主要增强点。旧插件原有的世界垃圾桶、公共垃圾桶、个人垃圾桶、清理通知、黑名单、保护功能等仍按兼容目标保留；这里重点只列重构版新增或明显增强的内容。

## 新增功能

### 公开品牌统一

公开插件名、消息与日志前缀、Java 入口类以及五个 dist 产物统一使用 `WorldListTrashCan`。正式长命令为 `/worldlisttrashcan`，简写为 `/wtc`；权限统一使用 `WorldListTrashCan.*`。PAPI 变量继续保持 `%Wtc_ClearTime%`。

### 轻量分包和通用总包

重构版同时提供两种交付形态：

- `WorldListTrashCan-legacy-1.12.jar`：面向 Paper/Spigot 1.12.2。
- `WorldListTrashCan-bukkit-1.13-1.15.jar`：面向 Bukkit/Spigot 1.13-1.15。
- `WorldListTrashCan-paper-1.16-1.20.jar`：面向现代 Paper。
- `WorldListTrashCan-folia-1.20.jar`：面向 Folia 1.20。
- `WorldListTrashCan-universal.jar`：通用总包，面向希望一个 jar 在高低版本和 Folia 之间切换的服主。

四个轻量分包仍是最小包体、最少运行时判断的推荐形态；通用总包保留同一套平台模块，但主类用 Java 8 编译，并在运行时延迟加载对应实现。这样既保留服主“一个 jar”使用习惯，也避免把 Legacy、Paper、Folia 差异堆在同一份运行逻辑里。

### Folia 专用安全清理链路

重构版新增 Folia 专用清理实现：

- `/wtc clear` 在 Folia 产物中改为异步启动语义。
- 世界实体扫描按 region/entity scheduler 分段执行。
- 物品删除、玩家通知等涉及实体或玩家的动作尽量提交到对应实体上下文。
- Folia 专用实体数量限制不使用普通 Bukkit 的跨 region 扫描。

注意：Folia 产物已完成后台 smoke 和多轮真实客户端回归，RGB Chat、ActionBar、Title 已有 Folia 客户端截图证据；清理通知专项也已用真实客户端覆盖 Chat、ActionBar、BossBar、Title，Sound 通过客户端字幕辅助证明触发，Command 通过服务端输出证明执行。当前仍不声明整包完全 `FOLIA_REGION_SAFE`，因为 Command 通知允许服主配置任意控制台命令。

### 扫地启动门禁

重构版新增扫地启动门禁，避免无人或低实体压力时仍触发完整扫地：

```yaml
guards:
  min-online-players: 1
  min-total-entities: 150
```

- `min-online-players`：在线玩家低于该值时跳过本轮扫地，默认 `1`，表示无人在线不扫地。
- `min-total-entities`：会被本轮扫地处理的目标实体数量低于该值时跳过本轮扫地，默认 `150`。
- 设置为 `0` 可关闭对应门禁。
- `/wtc clear` 和 `/wtc clear` 默认忽略 `guards` 门禁；需要验证或手动执行门禁时使用 `/wtc clear false` 或 `/wtc clear false`。
- `/wtc stats` 会显示最近一轮门禁状态；自动扫地被门禁跳过时会发送 `cleanup.yml` 中 `notify.*.messages` 的 `-5` 提示。
- 普通 Bukkit/Paper/Legacy 端在达到阈值前只暂存少量候选实体，达到阈值后继续清理，避免为了门禁做完整二次扫描；Folia 端按 RegionScheduler 先做安全计数，达到阈值后再进入清理阶段。

### 默认阻止世界垃圾桶强制加载区块

旧版世界垃圾桶可能在清理时访问未加载区块，导致同步加载区块并造成卡顿。重构版新增默认保护：

```yaml
world-trash:
  allow-load-unloaded-chunks: false
```

默认情况下，如果世界垃圾桶所在区块未加载，清理任务会跳过该箱子并按路由降级，而不是强行加载区块。

### 拆分配置文件和中文注释

重构版把旧的大配置拆成多份文件：

- `config.yml`
- `cleanup.yml`：清理周期、清理规则和清理通知。
- `trash.yml`
- `entity-limits.yml`
- `protections.yml`
- `platform.yml`
- `messages/message_*.yml`
- `data/worlds.yml`

默认配置均带中文注释，更适合后续维护、迁移和排查。

### 公共垃圾桶字符布局

公共垃圾桶 GUI 不再固定为六行、前 45 格内容和固定的第 46/52 格翻页按钮。`trash.yml` 的 `global-trash.gui.layout` 支持用单字符配置 1-6 行菜单，每行固定 9 格，并通过 `items.<字符>.type` 定义 `content`、`previous-page`、`next-page` 和 `background`。

展示物支持按顺序尝试多个 Material、CustomModelData、RGB/传统颜色名称和 Lore，并支持页码占位符。首页或末页没有可翻页目标时，可以通过 `unavailable-item` 改为显示指定背景物品。错误布局会输出具体中文原因并回退默认布局，不会尝试创建超过原版 54 格上限的 GUI。

布局容量允许在 reload 时缩小。旧存量无法全部进入新正常容量时，插件会追加只承载旧物品的临时溢出页；这些页面可以翻页查看和取出，但新路由不会继续写入溢出页，从而避免缩容时静默删除公共垃圾桶内容。

2026-07-21 已使用当前 `dist/WorldListTrashCan-universal.jar` 在 Paper 1.12.2 和 Folia 1.21.8 上完成真实客户端专项。两端真实 F2 截图均显示 2 行小布局、翻页按钮、名称/Lore 和 3 个旧存量堆叠所在的临时溢出页；客户端点击取出一堆后，正常页首格变空且物品进入玩家背包。服务端断言同时证明缩容前后始终保留 12 堆、溢出页不接收新物品、正常页释放容量后恢复写入，并验证 7 行错误布局回退 6 行。证据目录：`docs/test-evidence/global-trash-layout-visual-20260721-024653/`。

### 控制台清理明细

`cleanup.yml` 新增独立的 `notify.console` 通道。控制台日志不再依赖玩家聊天开关，清理完成后会按“自定义名、`getName()`、`getType()`”的降级顺序统计实体，并按数量从高到低输出。默认显示前 10 个实体名称与类型组合，可通过 `max-entries` 增加到最多 100；剩余实体合并到 `others`。

物品使用实际数量统计：一组 64 个物品计为 64。统计范围包含成功进入世界、个人、公共垃圾桶以及无法入桶后直接删除的物品，与 `%DealItemSum%` 保持一致。实体名称会移除颜色和控制字符，同名不同颜色不会被拆成多组。Folia 仅保存清洗后的字符串计数，不跨 region 保存实体对象。

### 旧配置自动迁移

重构版会识别同名 `plugins/WorldListTrashCan` 目录中的旧结构并迁移到新拆分结构：

- 根目录旧文件、自定义文件和日志会全部移动到 `old-version-config/`，不再直接生效。
- 新配置先在 `.migration-staging/` 生成和校验，再发布到根目录。
- 报告写入 `old-version-config/migration-report.md`；全部成功后才生成 `migration-complete.yml`。
- 迁移支持中断重试；完成标记存在后不重复迁移，根目录重新出现旧结构时拒绝启动。
- 已承接主配置、清理配置、通知配置、保护配置、实体限制配置、公共/个人/世界垃圾桶配置，以及旧世界垃圾桶运行数据。
- 旧公共垃圾桶按钮的 `Material` 与 `ModelId` 会迁移到新字符布局；旧语言文件逐文件原样备份，未知旧字段自动列入人工确认报告。
- 损坏 YAML、损坏完成标记、新旧结构混放或备份冲突时会拒绝启动，不覆盖旧输入，也不会伪造完成标记。
- 当前 universal 整包已完成 Paper 1.12.2 完整正负向矩阵、Spigot 26.1.2/Folia 1.21.8 跨端矩阵和真实 Forge 1.12.2 客户端可见验收。

### 多语言消息服务

重构版新增统一消息服务，支持：

- 简体中文：`message_zh.yml`
- 繁体中文：`message_zh_TW.yml`
- 英文：`message_en.yml`
- 西班牙语：`message_es.yml`

如果旧服已有外部语言文件但缺少新节点，正式玩家文案会优先回退到当前语言对应的 jar 内置节点，再回退到默认中文节点，减少升级后提示空白的问题。旧外部语言文件如果仍把调试命令堆在 `command.help` 主帮助里，运行时会改用当前语言的 jar 内置主帮助，避免英文语言切换时被强制退回中文主帮助。

### 个人垃圾桶自动回收提示

旧版公共垃圾桶已有提示，重构版新增个人垃圾桶自动回收提示：

- 单个掉落实体被仙人掌、岩浆、虚空等损坏回收时，逐条提示。
- `/wtc clear` 或后台扫地一次回收多个掉落物时，合并为一次批量提示。
- 批量提示最多展示多少类物品可在 `trash.yml` 配置。
- 物品列表格式、分隔符、省略号都可在语言文件配置。

示例：

```text
[WorldListTrashCan] 已回收到个人垃圾桶: [STONE*2]
[WorldListTrashCan] 本次清理已回收到个人垃圾桶: [STONE*5, COBBLESTONE*30, DIRT]
[WorldListTrashCan] 本次清理已回收到个人垃圾桶: [STONE*5, COBBLESTONE*30, DIRT, ...]
```

### 玩家丢弃物归属追踪增强

重构版增强了玩家主动丢弃物进入个人垃圾桶的判断：

- Legacy 1.12 和 Bukkit 1.13-1.15 没有 PDC，因此使用短期运行态 owner 追踪。
- Paper/Folia 优先使用掉落实体 PDC 标记 owner。
- Paper/Folia 的 owner 标记写在掉落实体上，不写入 `ItemStack` 元数据，避免隐藏 PDC 影响物品正常叠加。
- 入库前会清理旧版本残留在物品元数据上的内部标记。

### 仙人掌、岩浆、虚空损坏回收模式

重构版把旧损坏回收行为拆成明确配置：

```yaml
personal-trash:
  damage-recovery:
    mode: "disabled"
    delay-seconds: 6
```

`mode` 可配置为：

- `disabled`：关闭。
- `global-trash`：进入公共垃圾桶。
- `personal-trash`：进入玩家个人垃圾桶。

### PAPI 变量覆盖到多平台产物

重构版四个平台代码都提供旧变量：

```text
%Wtc_ClearTime%
```

该变量返回下次自动清理剩余秒数。Legacy、Bukkit、Paper 已使用 PlaceholderAPI 2.11.6 完成运行态验证；Folia 1.21.8 已使用支持 Folia 的 `[PAPI]PlaceholderAPI-2.11.7-DEV-null (1).jar` 和最终 universal jar 完成运行态验证。

重构版新增和保留了一批后台测试入口，方便服主或开发者验证真实运行态。调试命令不会在 `/wtc help` 主面板里完整展开，需单独使用：

## 兼容增强

### 正式命令和权限

重构版公开命令入口：

```text
/worldlisttrashcan
/wtc
```

正式权限节点包括：

- `WorldListTrashCan.Admin`
- `WorldListTrashCan.Main`
- `WorldListTrashCan.GlobalTrashOpen`
- `WorldListTrashCan.PlayerTrash`
- `WorldListTrashCan.GlobalTrashTakeItem`
- `WorldListTrashCan.PersonalTrashTakeItem`
- `WorldListTrashCan.DropMode`
- `WorldListTrashCan.Look`

### OP 旁路行为恢复

OP 可以绕过管理命令和公共/个人垃圾桶 GUI 取放物品等权限限制。

### 世界垃圾桶上限运行数据生效

重构版让 `/wtc add <世界名> <数量>` 写入的 `data/worlds.yml` 上限参与正式创建判断，不再只验证文件落盘。

### 公共黑名单保存即时生效

公共黑名单 GUI 保存后会刷新运行期配置，不再要求服主手动 `/wtc reload` 才完全生效。

公共黑名单 GUI 采用 token 点击模型，避免旧实现依赖原版光标物品导致关闭 GUI 时保存为空。玩家点击自己背包里的物品时，只会在上方黑名单 GUI 复制一个 Material token，不会消耗玩家背包物品；点击上方 token 会删除该黑名单项；关闭 GUI 后写回 `trash.yml` 并立即刷新运行期配置。2026-07-02 已用 Spigot 26.1.2、Paper 1.12.2、Folia 1.21.8 三端真实客户端矩阵验证：`STONE` token 保存到 `global-trash.banned-materials` 后，`debugroute ... global STONE 1` 返回 `routed=false`。

### 个人垃圾桶 Vault 扣费专项验收

`trash.yml` 的 `personal-trash.take-cost` 大于 `0` 时，玩家从个人垃圾桶取出物品会通过 Vault Economy 扣费；默认 `-1` 表示不扣费。2026-07-02 已用 `dist/WorldListTrashCan-universal.jar`、Spigot 26.1.2 managed 和真实 26.1.2 客户端完成专项验收，脚本 `tools/rgb-visual-matrix/run_vault_payment_matrix.py` 会临时提供插件名为 `Vault` 的 fake Economy 前置并点击个人垃圾桶 GUI。

本轮验证三种关键场景：余额充足时取出成功且余额从 `$100.00` 扣到 `$90.00`；余额不足时物品保留在个人垃圾桶且不扣费；玩家主背包已满时物品保留在个人垃圾桶且不扣费。重构版现在会先确认玩家主背包存储槽能完整接收物品，再调用 Economy 扣费，避免旧逻辑出现“扣费成功但物品没取出”的问题。最终被测 jar SHA256 为 `18d92a709d48fc291dd77c74a3be7d543f5bb20fa0fc01c4c70ab00eb33773d4`，证据目录为 `docs/test-evidence/vault-payment-visual-20260702-200346/`。

## 当前注意事项

- Folia 的 PAPI 变量需要支持 Folia 的 PlaceholderAPI 前置；旧 PlaceholderAPI 2.11.6 不支持 Folia，本轮验证使用的是 `[PAPI]PlaceholderAPI-2.11.7-DEV-null (1).jar`。
- Folia 清理通知里的 Chat、ActionBar、BossBar、Title、Sound 和 Command 已有真实客户端专项验收；仍需注意 Command 通知可执行服主自定义控制台命令，不能因此声明任意命令都 region-safe。
- PrismaticAPI 当前按 `GPL-3.0-only` 许可证接入，本重构版按后续开源基础版发行前提使用；如果未来要做不满足 GPL-3.0-only 要求的闭源发行，需要重新评估 RGB 库或改为外置依赖。
- Folia 密集实体限制已改为低占用分片扫描：region 内采集 chunk 快照，异步候选队列按预算删除，并通过 chunk 索引支持半径范围内的跨 chunk 计算。
- `debug*` 命令会改变测试服运行态，只建议用于测试服。
- 混用旧外部配置时，建议先备份 `plugins/WorldListTrashCan` 和 `plugins/WorldListTrashCan`。
