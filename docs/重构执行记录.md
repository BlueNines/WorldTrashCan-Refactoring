### 首轮失败

首次启动暴露真实兼容错误：

```text
java.lang.NoSuchFieldError: Class org.bukkit.Material does not have member field 'org.bukkit.Material STAINED_GLASS_PANE'
```

修复：

- `GlobalTrashService` 不再直接引用 `Material.STAINED_GLASS_PANE`。
- 改为按字符串顺序解析 `BLACK_STAINED_GLASS_PANE`、`STAINED_GLASS_PANE`、`LEGACY_STAINED_GLASS_PANE`、`GRAY_STAINED_GLASS_PANE`、`GLASS_PANE`、`THIN_GLASS`。
- 所有候选都不可用时退回 `Material.STONE`。

## 2026-06-02 仙人掌和岩浆损坏回收补齐

用户继续要求补齐旧功能。本轮复盘旧插件 `Set.PersonalTrashCan.OriginalFeatureClearItemAddGlobalTrash` 后，确认新实现此前只做了 PDC owner 标记，没有承接旧配置里的 `UseModel` 和 `Delay`。

### 实现内容

- `TrashConfig.PersonalTrashConfig` 新增 `damageRecoveryMode` 和 `damageRecoveryDelaySeconds`。

## 2026-06-02 Folia region-safe 清理入口补齐

前面 Folia 首轮 smoke 已证明普通 Bukkit 风格的 `world.getEntities()` 不能放在 global scheduler 上。本轮继续收口旧功能时，先把 Folia 清理从“拒绝危险扫描”推进到“专用 region/entity scheduler 清理”，但不把整产物声明为 `FOLIA_REGION_SAFE`，因为共享实体数量限制还没有 Folia 专用实现。

### 实现

- 新增 `FoliaRegionCleanupFeature`：
  - global scheduler 只负责收集世界和已加载 chunk。
  - 每个 chunk 交给 `Bukkit.getRegionScheduler().run(...)` 读取 `chunk.getEntities()`。
  - 物品所在 region 只读取物品实体和快照。
  - 世界垃圾桶写入先取位置快照，再切到箱子所在 region 调 `routeWorldTrashAt(...)`。
  - 路由成功后通过 `item.getScheduler().execute(...)` 回到物品实体 region 删除掉落物。
  - 清理统计使用线程安全增量方法累计，完成后输出 `[FoliaCleanup]` 汇总日志。
- `BLWorldTrashCanFoliaPlugin` 不再注册共享 `CleanupFeature`，改注册 `FoliaRegionCleanupFeature`。
- Folia `/blwtc clear` 改为异步启动语义：命令只提示已启动，最终结果看后台 `[FoliaCleanup]` 或后续 `/blwtc stats`。
- `FoliaPlatform` 增加 `SCHEDULER_REGION` 能力，但仍不声明 `FOLIA_REGION_SAFE`。
- Folia 产物暂不注册共享 `EntityLimitFeature`，避免 `world.getEntities()` / `getNearbyEntities()` 在 Folia 上跨 region 访问。
- Folia 后台测试入口 `debugworldtrash`、`debugroute`、`debugdrop`、`debugdamage` 改为提交到玩家实体 scheduler 执行，减少测试命令自身造成的 Folia 线程噪声。

## 2026-06-02 Folia 专用实体限制补齐

上一轮 Folia 清理补齐后，旧功能矩阵里还剩实体数量限制在 Folia 产物中被安全禁用。本轮补 Folia 专用实现，避免共享 `EntityLimitFeature` 里的 `world.getEntities()` 和 `getNearbyEntities()` 跨 region 访问。

### 实现

- 新增 `FoliaEntityLimitFeature`。
- 通过 `EntityAddToWorldEvent` / `EntityRemoveFromWorldEvent` 维护 `world + entityType` 数量缓存。
- 启用实体限制时，使用 global scheduler 分派已加载 chunk，再用 `RegionScheduler` 在 chunk 所在 region 内读取 `chunk.getEntities()`，定期复算缓存。
- `CreatureSpawnEvent` 中按缓存判断单世界实体上限；放行时立即按实体 UUID 预占计数，避免同一 tick 连续生成绕过上限，后续 `EntityAddToWorldEvent` 用 UUID 去重，不会双计数；如果实体没有进入可调度状态或下一 tick 已无效，会释放预占计数。
- 密集实体限制不再调用 `getNearbyEntities()`，只扫描当前 chunk 内、半径范围内的同类型实体；这是为了保持 Folia region-safe，代价是跨 chunk 边界的密集实体不会在这一轮被同一次生成事件清理。
- `BLWorldTrashCanFoliaPlugin` 接回实体限制功能，但注册的是 Folia 专用 `FoliaEntityLimitFeature`。
